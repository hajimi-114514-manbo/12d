## 1. 现状锚点（接入点均为真实代码）

- 预览链：`VideoWorkbench.render_frame(t)` → `video_export.compose_frame(proj, t, src_get)`
  （numpy RGBA）→ `StageView.set_frame(arr, proj, t)`（`stage_view.py:54`）。
- StageView：`QWidget` 自绘（`_build_pixmap` 贴帧 + QPainter 画选中框/手柄/字幕），

  交互门控字段 `playing/tick_busy`（workbench 写入）。

- WebGAL 运行时：`templates/webgal_runtime/`（按需下载，E1b），内含

硬规则（H3 实现卡验收项）：

1. workbench 内一切引用包在 `if webgal_preview.available():` 后；

4. WebEngine 不进安装包；提供方式（可选组件/按需提示）是发行决策，另行立项。

## 3. 桥接协议（对齐 J2 `puppetAPI`）

### 3.1 Envelope（两形态共用）

```json
{"v":1, "id":42, "cmd":"playMotion", "args":{"name":"<role>/idle01","loop":true,"fadeMs":200}}
{"v":1, "ref":42, "evt":"ready", "data":{"modelId":"<model_id>"}}
```

- `v` schema 版本（只增字段不改语义）；`id/ref` 命令-回执关联。
- 命令语义幂等：v3 是"状态同步器"不是"事件重放器"——页面永远只需知道
  **当前**状态；迟到的旧命令可安全地被新状态覆盖。

### 3.2 命令表（v3 → 页面；页面侧对应 puppetAPI 方法）

| cmd | args | puppetAPI 映射 | 语义 |
|---|---|---|---|
| `loadModel` | `{modelRef, modelId}` | `loadModel(url)` | 装载 `muppet://…/model.json`；同 ref 重复=无操作；完成回 `ready` |
| `clearModel` | `{modelId?}` | `stop()`+卸渲染 | 离场/换工程；modelId 空=全清 |
| `setTransform` | `{x,y,scale,rot}` | 页面内设置（J2 原型 `_settings`） | 与 `video_model.layout_at` 同源坐标 |
| `playMotion` | `{name,loop,fadeMs?}` | `playMotion(name)` | 键名已由 v3 白名单校验；未知→`error{unknownMotion}` |
| `setExpression` | `{name,fadeMs?}` | `setExpression(name)` | 独立通道；未知→`error{unknownExpression}` |
| `setPaused` | `{paused}` | 页面冻结/恢复时钟 | scrub 暂停预览时用（可选实现） |
| `seek` | `{t}` | （J2 待验证） | 动作相位对齐 `t−clip.start`；不可行回 `error{seekUnsupported}`，v3 退化为重发（§4） |

### 3.3 事件表（页面 → v3）

| evt | 载荷 | v3 处置 |
|---|---|---|
| `ready` | `{modelId}` | 状态机 PENDING→READY，补发挂起状态 |
| `error` | `{code,msg,ref?}` | 记日志；模型级错误连续 3 次 → 本会话自动关实时预览并置灰开关 |
| `motionDone` | `{name}` | **v3.5 不接线**（时间轴语义里没有"动作结束帧"，节奏由台词游标决定；仅留观测） |

J2 草案三个开放问题的裁决：**资源协议**=§2.1 `muppet://`；**ready**=`evt:ready`
+状态机补发；**动作结束**=`motionDone` 预留不消费。

### 3.4 传输适配

- **A 形态（J2 主路线）**：注入 `qrc:///qtwebchannel/qwebchannel.js`，页面引导
  连 `QWebChannel`；Python 侧 `class MuppetBridge(QObject)`：`cmdReceived =
  Signal(str)` 下行、`@Slot(str) postEvent(json)` 上行。
- **B 形态（J2 兜底：整页 WebGAL）**：`QWebEngineScript`(DocumentCreation)
  注入桥脚本 `window.__muppet = (jsonStr) => 转调 WebGAL 内部 charApi 面`；
  下行 `page.runJavaScript("window.__muppet && window.__muppet(%s)")`；上行
  `fetch("muppet://event/"+payload)` 由 scheme handler 收下即事件。映射不到的
  命令回 `error{cmdUnsupported}`（B 形态 seek/setPaused 预期不支持，D5 退化）。
- workbench 只见一个入口：`WebPreviewView.apply_state(state: PreviewState)`；
  A/B 是内部 Transport 子类差异（工厂参数 `A_HOST_PAGE|B_RUNTIME_PAGE`）。

## 4. 状态同步时机（diff 驱动）

`PreviewState = figures: [(clip_id, modelRef, layout, motion, expression)]`，
= 该 t 时刻生效立绘 clip（`video_model.figure_clips_at(proj, t)` 同源口径，
I1 之后此函数已存在且被 remote/import/export 三方复用——预览直接消费，
**不再新造遍历**）。

| 触发（现有代码位点） | 动作 | 节流 |
|---|---|---|
| `render_frame(t)` 播放中 | 只算 figures diff：入场→`loadModel`+transform+motion；离场→`clearModel`；**同 clip 内不发 seek/不重发动作**（页面自走） | diff 空零流量 |
| StageView 拖框（`layout_changed`） | 单 clip `setTransform` | 30ms trailing |
| 时间线 scrub / `timeline.seek` | figures 集合 diff；seek 若 J2 证明可行则附 `{t}`，否则跨 clip 才重发 | 80ms debounce |
| 属性面板动作下拉（`_motion_changed`） | `playMotion/setExpression` | 即时 |
| 工程切换 / `project.new` / DSH 载入 | `clearModel` 全清 | 即时 |
| 开关关闭 | 停发状态 + `setPaused(true)`，视图保活（再开秒回） | — |

与 remote_control 的关系（D6）：预览不新增任何 remote 命令；DSH 改工程
（say/figure.*/script.import）后主线程 `render_frame` 本来就会被调，diff
同步自动跟上——零接口、零队列竞争。

## 5. 视图共存与交互分工（推荐已定）

```
预览区（video_workbench.py:306 处）
└── QStackedLayout（替换 cl.addWidget(self.stage, 1)）
    ├── page0: StageView          永远在场：画面(实时态可透明) + 全部鼠标交互
    └── page1: WebPreviewView     懒创建；WA_TransparentForMouseEvents
```

- 模式语义：**布局态**=现状 QPainter 帧 + 交互框；**实时态**=WebEngine 画面
  为底、StageView 半透明覆盖继续提供选中框/拖拽手柄（`set_frame` 传空帧仅
  画 UI）。切换=stacked index + 一个开关（预览区角标，仅 `available()` 显示）。
- 推荐依据：①写回链路唯一（`layout_changed→push_history→video_model`），
  撤销/属性面板/时间轴联动零改动；②页面内拖框要求 js 端重写命中/吸附/历史，
  成本收益失衡；③B 形态下整页是第三方 DOM，注入手势根本不可控。
- 一致性：实时态切回布局态时上一帧 RGBA 立即回填（StageView 从未销毁），
  不闪白；导出画面永不受开关状态影响（§6）。

## 6. 导出不回抓 WebEngine 帧（论证）

结论：**`paste_layer` 合成链是导出/快照/渲染唯一链路，回抓方案否决**。

1. **确定性**：compose_frame 纯函数（numpy/cv2），同工程同 t 跨机器逐字节
   一致——video_export/video_layout 等回归测试体系靠这个吃饭。WebEngine
   出帧经 GPU/ANGLE/合成器，跨驱动不一致 + 异步时序抖动，导出不可复现。
2. **线程模型冲突**：MP4/GIF 导出逐帧合成、允许离屏/并行；
   `QWebEngineView.grab()` 必须主线程且每帧等渲染循环——帧率坍缩且与 UI
   互锁，直接摧毁"后台导出"体验。
3. **可选件约束**（D2 同源）：导出不能依赖可能不存在的组件；无 WebEngine
   安装包是**当前发行形态**，导出必须照常。
4. **视觉缺口已有兜底**：导出侧 puppet clip 用 H2 图集占位帧，用户已在
   「预览=导出」的既定语义下工作；实时预览的价值主张是**布置辅助**
   （摆位/选动作的所见即所得），不是渲染器。
5. 若未来要"高保真单帧快照"（人工按钮级），可作为独立功能评估 grab()，
   永不进导出管线——协议无需为此预留消息。
