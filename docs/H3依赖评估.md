> 实测环境：Windows 11，Python 3.12（D:\Python312），PySide6 6.12.0（Essentials+Addons），
> 实测日期 2026-11-14。原型页见 `webgal_games/preview_proto/`（task-51）。

## 1. 安装

- **安装前状态**：未装（`import PySide6.QtWebEngineWidgets` → ModuleNotFoundError）。
- **版本对齐**：pip 包名 `PySide6-WebEngine`，**版本号不是 6.12.0 而是
  `6.12.0.140`**（Qt for Python 自 6.7 起 patch 位带 build 号；
  `pip install PySide6-WebEngine==6.12.0` 会报 no matching distribution）。
  已装 `PySide6-WebEngine==6.12.0.140`，与现有 Essentials/Addons 6.12.0、
  shiboken6 6.12.0 完全同源，安装即用，无冲突。
- **体积**：site-packages 下载 ~90MB，落盘后 WebEngine 相关 **339MB**（明细见 §3）。

## 2. offscreen 行为（实测，与预期相反）

**结论：offscreen 下 QWebEngineView 完全可用**，无需为测试套件做 HAS_WEBENGINE
条件跳过以外的特殊处理。

实测（`QT_QPA_PLATFORM=offscreen`）：

| 操作 | 结果 |
|---|---|
| `QWebEngineView()` 构造 + `show()` | 成功 |
| `load(QUrl.fromLocalFile(本地 html))` | 成功 |
| `page().toHtml(cb)` | 回调拿到完整 DOM（7459 字节） |
| `view.title()` | 正确读出页面 `<title>` |
| `view.grab()` 截图 | 成功，页面渲染正常（真 GUI 下复核） |
| `page().runJavaScript(js, cb)` 桥接 | 成功（能读页面内 #log 文本） |

Chromium 有自己的合成器，不依赖 Qt 平台插件的 GUI 能力，offscreen 平台插件
6.12 下对 WebEngine 支持良好。**但注意两点**：

1. **首次构造必须先建 QApplication**，且进程需持有 `QApplication`（不能
   QCoreApplication——WebEngine 要事件循环 + widget 层）。
2. **多进程**：每次运行会派生 `QtWebEngineProcess.exe` 子进程；offscreen 测试
   收尾若直接 `os._exit`，子进程可能残留 1-2 秒，测试框架要容忍（或收尾前
   `view.deleteLater()` + `processEvents`）。现有测试的收尾模式
   （close + deleteLater + processEvents 循环）已够用。

真 GUI 复核（补充）：窗口截图 `D:\scripts\temp\webengine_gui_smoke.png`——
QWebEngineView 正确渲染 task-51 原型页（按钮/面板/log 区），`runJavaScript`
双向桥通。

**测试套件策略**：仍建议 `HAS_WEBENGINE = importlib.util.find_spec(
"PySide6.QtWebEngineWidgets") is not None` 条件导入 + `skipUnless(HAS_WEBENGINE)`
——不是因为 offscreen 不可用，而是因为 **打包后的整合包运行时可能没带 WebEngine**
（见 §3 路线 b），测试要在两种安装形态下都能跑。

## 3. PyInstaller 打包评估

### 体积构成（site-packages\PySide6 实测）

| 文件/组 | 体积 | 是否必需 |
|---|---|---|
| Qt6WebEngineCore.dll | **194.1 MB** | 必需（Chromium 内核本体） |
| qtwebengine_devtools_resources.debug.pak | 72.3 MB | **可剔除**（开发者工具） |
| qtwebengine_devtools_resources.pak | 11.1 MB | 可剔除（同上非 debug 版） |
| icudtl.dat | 10.0 MB | 必需（Unicode 数据） |
| qtwebengine_resources.pak | 2.2 MB | 必需 |
| 各语种 locale pak（~40 个） | ~40 MB | 可只留 zh_CN（~1.4 MB） |
| QtWebEngineProcess.exe | 0.8 MB | 必需（Chromium 沙箱子进程） |
| **合计（原始）** | **~339 MB** | 裁剪后必需 ~**209 MB** |

### 两条路线对比

**a) 打进主包**

- 增量：~209MB 原始 → 7z/zip 压缩后（DLL 实测压缩率 ~50%）约 **100-110MB**。
- Setup 现状 49.28MB → 预计 **~150-160MB**。
- 代价：所有用户（含不用预览/不玩 WebGAL 导出的）都背这 100MB；
  Setup 下载时间显著变长（按 hf-mirror 实测 0.5-4MB/s 波动，多 30s-3min）；
  安装器 49MB blob 走 GitHub Release 已有上传被掐的前科（E1 记录：49MB 两次
  传挂），150MB 风险更高。
- 收益：装完即用，无二次下载。

**b) 可选资产走 asset_downloader（像 WebGAL runtime 那样）**

- 现成机制：asset_catalog.ASSETS 加 `id="preview_webengine"` 条目
  （url 指向自托管 zip，zip_sha256 钉死），AssetDownloadThread 单包模式
  断点续传 + sha256 fail-closed 校验 + 解压到 `runtime/`——**E1b 已端到端
  验证这条链路（50MB 真实下载成功）**，WebEngine zip 只是更大一号的包。
- 运行时布局：解压到 `<安装目录>\runtime\webengine\`，启动时把该目录
  注入 `os.addDllDirectory` / `QTWEBENGINE_*` 环境变量即可让已装 PySide6
  加载（PySide6 的 DLL 搜索兼容插件式布局；需在真机验证一次 DLL 解析，
  预研未覆盖——**唯一残留风险点**）。
- 代价：用户按需多下 ~110MB（压缩包），首用预览时多一次下载等待；
  版本对齐要自律（WebEngine 资产版本必须与整合包内 PySide6 严格一致，
  资产清单写死 sha256 与版本号，upgrade 流程与 cuda_pack 同款）。
- 收益：Setup 保持 ~49MB；只有用 H3 预览功能的用户付出代价；下载链路
  断点续传/镜像回退/校验全部现成。

### 推荐：**路线 b（可选资产）**

理由：

1. **受众错配**：H3 预览是进阶功能；多数用户主链路是拆图/骨架/导出，
   不该为他们付 2-3 倍 Setup 体积。
2. **机制现成**：asset_downloader 的单包模式（sha256 fail-closed + 断点续传
   + 镜像回退）已被 E1b 真实 50MB 下载验证；cuda_pack 已验证 GB 级分卷。
   加一个资产条目的成本 ≈ 一天（含构建脚本 + 上传 + 清单）。
3. **Setup 体积红线**：GitHub Release 49MB blob 上传已有失败前科；150MB
   会把发布流程变成高风险环节。拆出去直接消掉该风险。
4. **回退自然**：WebEngine 资产未装时，H3 预览退化为「嵌 WebGAL 整页
   （路线 B）」的提示卡或跳浏览器打开——功能可降级，主流程零影响。

### 残留风险（转 H3 实施前验证）

- [ ] 路线 b 的 DLL 异地加载：PySide6 Qt6WebEngineCore.dll 不在
      site-packages 时能否经 `os.addDllDirectory`/PATH 注入加载（需真机
      一次性验证；不行就解压到 site-packages 旁边 = 用户目录，一样可控）。
- [ ] PyInstaller 打包 WebEngine 的标准 hook（PyInstaller-hooks-contrib
      已内置 PySide6 WebEngine hooks），走路线 a 才需要；路线 b 不涉及。
- [ ] 杀软对 QtWebEngineProcess.exe 子进程模型的误报率（主包内嵌时）；
      路线 b 解压到用户目录同样要过 SmartScreen——历史上 runtime.zip
      解压无此问题，风险低。
